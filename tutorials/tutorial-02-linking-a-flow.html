How to use this page: Follow each numbered step in Figma. You can jump between sections using the topic list, or print this page from your browser. The exercises use your own practice file; your team determines its separate project organization.

Before you begin

Open your existing exploration file at 2026 UX Design (Fall) → Team [number] → Explorations & Demo → [Your first name]. You should already have 02 – Components and 03 – Screens, the Trip / Card component, its On time / Changed / Cancelled variants, and your styles from Workshop 1.

What you'll make: A reusable CTA button and Navigation Bar, plus a clickable prototype that goes from an upcoming shuttle trip to details, interrupts with a Red Alert, and lands on a Cancelled trip state.

1. Prepare your screens and flow starting point

0–4 min · Prototype setup

  1. Open 03 – Screens and rename your existing phone frame 01 / Upcoming Trips. Keep the On time trip-card instance visible.
  2. Leave room below that card for a View trip action. You will add a reusable CTA button next.
  3. Duplicate the phone frame and name the copy 02 / Trip Details. This will show trip information and a Simulate red alert action.
  4. Duplicate the details frame again and name it 03 / Trip Cancelled. Keep the card instance where it is; in Section 4 you will change its Status to Cancelled. Add the message: “Shuttle S-04 has been cancelled. Boarding is suspended.”
  5. Select the top-level 01 / Upcoming Trips frame. Switch to the Prototype tab in the right sidebar.
  6. Under Flow starting point, click + and name the flow Shuttle status interruption.

Remember: A flow starting point belongs to a top-level screen frame, not to a layer inside the card.

2. Create a reusable CTA button

4–7 min · An Auto Layout component

  1. Open the 02 – Components page.
  2. Press T and type Button. Apply your Body / Regular text style.
  3. Select the text and press Shift + A to add Auto Layout. Rename the frame cta-button.
  4. Set alignment to Center; horizontal padding to 16 px and vertical padding to 10 px. Keep width and height Hug contents.
  5. Select cta-button and apply the Action / Primary style to its Fill.
  6. Select the Button text layer and apply Surface / Default to the text fill (white).
  7. Set the cta-button corner radius to 8 px.
  8. Select cta-button and Create component (Mac: Option + Command + K). Leave the main component on 02 – Components.
  9. On 03 – Screens, place a cta-button instance on Upcoming Trips; change its label to View trip. Place another instance on Trip Details; change its label to Simulate red alert.
  10. Select the Simulate red alert button instance on Trip Details. In the right sidebar, override that instance's fill from Action / Primary to red (for example, #B42318). Leave its text white using Surface / Default.
  11. If you want the CTA to span the screen content width, set the instance to Fill container inside your screen-content Auto Layout frame. Keep its height Hug contents.

Do not edit the main CTA component to red. The red fill is an instance override on the Simulate red alert button. Other buttons stay blue.

3. Build a reusable Navigation Bar

7–15 min · Status bar, Back, Title, and Profile

A. Make the Back button

  1. Open 02 – Components. In Figma Resources / Assets, search for “iPhone status bar” and insert a status bar instance for a 402 px-wide phone.
  2. Press T, type Back, and apply Body / Regular.
  3. Select Back and press Shift + A. Set the direction to Horizontal, align items to Center, and temporarily name the frame back-container.
  4. Search Figma Resources / Assets for a Material Design back icon, such as arrow_back or chevron_left.
  5. Drag the icon before the word Back within that Auto Layout container. Set an appropriate icon size (about 20–24 px) and a small gap (4–8 px).
  6. Rename the Auto Layout frame back-button.

B. Add the navigation content

  1. Create text reading Title; apply your existing Heading / Medium style.
  2. Create text reading Profile and apply Body / Regular.
  3. Select Profile and press Shift + A. Name the resulting frame profile-container.
  4. Select the three sibling layers: back-button, Title, and profile-container.
  5. Press Shift + A to wrap them in horizontal Auto Layout.
  6. Set Gap = Auto (Space between), vertical alignment = Center, and horizontal padding = 16 px.
  7. Name the frame nav-content.

C. Assemble, publish as a component, and place instances

  1. Select the iPhone status bar instance and nav-content, then press Shift + A to make a vertical Auto Layout parent.
  2. Rename the parent frame Navigation Bar and set Gap = 0.
  3. For the sample phone, use 402 px as the Navigation Bar width and Hug contents for height. Set nav-content to Fill container width; make the imported status bar fit the same width if needed.
  4. Select the Navigation Bar and choose Create component. Keep the main component on 02 – Components.
  5. On 03 – Screens, add a Navigation Bar instance to each of the three phone screens, above screen-content:
    • 01 / Upcoming Trips
    • 02 / Trip Details
    • 03 / Trip Cancelled
  6. Override Title in each instance to match its screen. Keep the whole Navigation Bar at the top of each phone frame.
  7. On 01 / Upcoming Trips, expand its Navigation Bar instance in the Layers panel, select the nested back-button, and hide that layer using the visibility (eye) control. Nothing comes before the first screen.
  8. Leave Back visible on 02 / Trip Details and 03 / Trip Cancelled. Hide the Back button only in the first screen's instance, not in the main component.

Layout note: Because your phone frame has 0 padding, the Navigation Bar can span the full 402 px. The separate screen-content frame keeps the trip content aligned to 16 px side margins. With Space between, the title may not be mathematically centered when the left and right controls have different widths; that's acceptable for this demo.

4. Link screens and choose the Cancelled variant

15–21 min · Navigate to vs. Change to

A. Connect View trip to Trip Details

  1. Open 03 – Screens and select the View trip button instance on 01 / Upcoming Trips.
  2. In the Prototype tab, drag the blue connector handle from the button to 02 / Trip Details.
  3. Set the trigger to On click / On tap and the action to Navigate to. Confirm that the destination is 02 / Trip Details.
  4. Keep the transition Instant for now; you will try Smart Animate in Section 6.
  5. On Trip Details, select back-button inside the Navigation Bar instance and add On click / On tap → Back.
  6. Preview: View trip opens the details; Back returns to the previous screen.

B. Select the existing Cancelled card variant

  1. On 03 – Screens, select the Trip / Card instance inside 03 / Trip Cancelled.
  2. In the right sidebar, find the component property Status.
  3. Choose Cancelled. Confirm that the component instance shows its Cancelled wording and visual style.
Prototype action What it does In our example
Navigate to Moves from one screen to another Upcoming Trips → Trip Details
Change to Switches to another variant during an interaction Concept only: On time → Changed within the same component set
Open overlay Shows a frame over the current screen Red Alert notice

Important difference: Choosing Cancelled in the right sidebar changes a design instance. It is not a prototype Change to action. We will not build an unnecessary Change to interaction just to set the final cancelled state.

5. Open a Red Alert overlay

21–27 min · An interruption without replacing the screen

  1. On 03 – Screens, create a separate Frame outside the phone screens. Name it Overlay / Red Alert. A starting size of approximately 320 × 210 px is fine.
  2. Add a prominent title RED ALERT.
  3. Add the message “Shuttle S-04 has been cancelled. Boarding is suspended.”
  4. Insert an instance of your cta-button component and change the label to View updated trip. Apply a clear, readable visual treatment; use both wording and color to communicate the warning.
  5. Select Simulate red alert on 02 / Trip Details and drag a prototype connector to Overlay / Red Alert.
  6. Set On click / On tap → Open overlay. Position it at Center, enable a dimmed background, and turn off Close when clicking outside for this important notice.
  7. Select View updated trip within the overlay. Connect it with On click / On tap → Navigate to → 03 / Trip Cancelled.
  8. Preview the full sequence: View trip → Simulate red alert → View updated trip. Confirm that the destination shows the Cancelled card state.

Pressure-map connection: A red alert is an external interruption in the crew member's world. The interface must clearly tell them that boarding is no longer available, without leaving an apparently valid On time trip behind.

6. Add Smart Animate

27–32 min · Try a smoother transition

  1. On 03 – Screens, compare 01 / Upcoming Trips and 02 / Trip Details. The duplicated screens should have some matching layers.
  2. In the Layers panel, check that the shared elements have matching layer names AND corresponding positions in the layer hierarchy. For example, their Navigation Bar, Trip / Card, and content groups should be organized consistently.
  3. Select the existing View trip → Trip Details prototype connection.
  4. In Interaction details, change the transition from Instant to Smart Animate.
  5. Choose a short duration, such as 300 ms, and a gentle easing option.
  6. Preview the transition. For a clearer demonstration, move or resize one matching element in Trip Details and preview again.
  7. If you see a fade rather than a smooth transition, check the names, nesting, and which properties changed.

Correction to remember: Smart Animate does not work on names alone. Matching names and hierarchy matter. Not every property or text replacement animates like position or size.

7. Preview, test, and share your prototype

32–36 min · Test the flow before you share it

  1. In the Prototype tab, find the flow Shuttle status interruption and open its Preview. You can also use Present.
  2. Start on 01 / Upcoming Trips, then try View trip → Simulate red alert → View updated trip.
  3. Confirm that the alert appears as an overlay, the final trip shows Cancelled, and no outdated boarding details look active.
  4. Test the Back button on secondary screens and confirm that the first screen has no visible Back control.
  5. If something does nothing, return to the design file and check the clickable layer, trigger, action, and destination.
  6. In presentation view, use Share prototype and Copy link. Check permissions so classmates can open it.
  7. Open the link separately to verify it starts at the correct flow starting point.

Tip: Share the prototype/flow link, not merely the design file URL. Available sharing controls may vary with Figma permissions and plan.

Completion checklist

  • CTA component: Body / Regular, blue Action / Primary fill, white text, 8 px radius
  • Simulate red alert CTA is a red instance override, not a red main component
  • Navigation Bar component includes status bar, back-button, Title, and profile-container
  • Navigation Bar instances appear on all three screens
  • Back is hidden only on Upcoming Trips
  • View trip uses Navigate to
  • Final screen's Trip / Card instance uses Status: Cancelled
  • Red Alert uses Open overlay
  • Overlay action goes to Trip Cancelled
  • Smart Animate was previewed
  • Prototype link opens the intended starting screen

Troubleshooting

Problem First thing to check
Flow starts on the wrong screen Flow starting point on the top-level 01 / Upcoming Trips frame
Tap does nothing Interaction trigger, clickable instance, action, and destination
Final card still says On time Select the final card instance; set Status: Cancelled in the right sidebar
Alert replaces the whole screen Use Open overlay, not Navigate to
Back is missing everywhere Hide the nested back-button in only the first instance
Navigation bar is inset or cropped Phone frame has 0 padding; screen-content has 16 px side padding
Smart Animate fades unexpectedly Matching layer names, hierarchy, and supported property changes
Other CTA buttons also turned red You edited the main component; revert and override only the red-alert instance
Classmates cannot open link Check prototype link permissions and flow URL

Optional independent challenge

Try an After delay trigger to display the Red Alert automatically, or prototype one more screen for an On time shuttle's boarding pass. Neither is required for this live demonstration.

How this supports the Starship Crew App

For the team project, apply the prototyping techniques to the one flow your behavior statement is about. Your final prototype should work from a single link, show how a crew member responds to a real pressure, and include working navigation so viewers never have to leave the prototype to understand the flow.
