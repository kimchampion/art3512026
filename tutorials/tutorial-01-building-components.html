Before you begin

This is an individual practice exercise for the Starship Crew App project. Each student works in their own Figma exploration file—not in the shared team project. The reusable parts you create today may later inform your team's design decisions.

Today's sample trip: Shuttlecraft Trip S-04 · Destination: Starbase 12 · Departure: 08:30 · Boarding bay: Bay 4 · Status: On time.

The seven activities (about 30 minutes):

1. Create your Figma exploration file

0–3 min · Individual setup

  1. Open Figma and navigate to the team 2026 UX Design (Fall).
  2. Open your assigned team folder: Team [number].
  3. Open the existing folder named Explorations & Demo.
  4. Create a new Figma Design file in this folder.
  5. Name it Shuttlecraft Trips. You do not need to add your name to the filename.
  6. Create three Figma Pages using the Pages section of the left sidebar:
    • 01 – Foundations
    • 02 – Components
    • 03 – Screens
  7. Keep this file for future demos. You do not need to invite teammates to your personal practice file.

Optional team folder example: Under 2026 UX Design (Fall) → Starship Champion (example), the instructor has Explorations & Demos, UI, Foundation, and Archive folders. Your team does not have to copy that structure. Decide together what will work best for your shared project.

2. Create a phone frame with a layout guide

3–7 min · A responsive structure for the card—and next workshop's navigation bar

  1. Open 03 – Screens. Press F to select the Frame tool.

  2. Choose a phone preset sized 402 × 874 px, or enter those dimensions manually.

  3. Rename the frame Shuttlecraft Trips.

  4. With the phone selected, find Layout guide (formerly Layout grid) in the right sidebar. Click +.

  5. Change the guide from a uniform grid to Columns, then set:

    | Property | Setting | |---|---| | Count | 4 | | Type | Stretch | | Margin | 16 px | | Gutter | 16 px |

  6. Add vertical Auto Layout to the phone frame using Shift + A. Keep the phone frame 402 × 874, with 0 px padding and 0 px gap. This lets a full-width navigation bar fit above the content in Workshop 2.

  7. Inside the phone frame, create a child frame named screen-content and apply vertical Auto Layout. Set its width to Fill container, height to Hug contents, and horizontal padding to 16 px. Use a suitable vertical gap, such as 16 px.

  8. We will place the trip-card instance inside screen-content. It should use Fill container width and Hug contents height.

Why both? The Layout guide is a visual alignment aid. Auto Layout controls how elements respond when content or available space changes. We are leaving the outer phone frame unpadded so the Navigation Bar in Workshop 2 can span the full width.

3. Create your atoms: text and color styles

7–12 min · Shared visual decisions

A. Make the text styles

  1. Open 01 – Foundations. Press T to create a text layer and type Shuttlecraft Trips.
  2. Choose a sans-serif font, such as Inter, and set it to 20 px / Semibold.
  3. In the Typography section of the right sidebar, open the style picker and create a text style named Heading / Medium.
  4. Create a second text layer, Departure, at 16 px / Regular.
  5. Save it as Body / Regular.

B. Make the color styles

  1. Press R and draw a small rectangle. Set its Fill to #1F2937.
  2. In the Fill style picker, create a style named Text / Primary.
  3. Repeat to create Surface / Default (#FFFFFF) and Action / Primary (#2563EB).
  4. Create the six additional semantic styles shown below. These styles have meanings that can be reused beyond the shuttle card.
  5. Apply Body / Regular and Text / Primary to your sample Departure text layer.
Color style Hex value Suggested use
Text / Primary #1F2937 Main text
Surface / Default #FFFFFF Default card background
Action / Primary #2563EB Primary action
Surface/Success #DDF4E5 On time badge background
Surface/Warning #F4ECDD Changed badge background
Surface/Danger #F4DDDD Cancelled badge background
Text/Success #216A43 On time badge text
Text/Warning #6A3C21 Changed badge text
Text/Danger #6A2121 Cancelled badge text

Teaching point: Surface / Default is the neutral surface. Success, Warning, and Danger are semantic style names, while On time, Changed, and Cancelled will be the component variant names. They serve different purposes.

4. Build a reusable detail-row molecule

12–17 min · Horizontal Auto Layout

  1. Open 02 – Components and create two text layers: Departure and 08:30.
  2. Apply Body / Regular and Text / Primary to each layer.
  3. Select both and press Shift + A to create an Auto Layout frame.
  4. Set the direction to Horizontal, gap to 8 px, height to Hug contents, vertical padding to 8 px, and horizontal padding to 0 px.
  5. If building the row by itself, you may temporarily preview it at 338 px wide. This is not a fixed requirement for the reusable row.
  6. Select Departure inside the row and set its width to Fill container. Keep 08:30 sized to its contents.
  7. Rename the frame Trip / Detail Row.
  8. Select the row and choose Create component (Mac: Option + Command + K).
  9. Duplicate the component as an instance, and change its labels to Boarding bay and Bay 4.

Quick test: Change Departure to Scheduled departure. Once the row is placed inside the trip-card Auto Layout container, its width should Fill container; longer labels can wrap. No minimum height is needed.

5. Assemble the trip-card organism

17–22 min · Vertical Auto Layout

A. Make a status label

  1. On 02 – Components, create a text layer reading On time.
  2. Select it and press Shift + A.
  3. Set horizontal padding 10 px, vertical padding 6 px, and both width and height to Hug contents.
  4. Apply Surface/Success to the container fill and Text/Success to the text fill.
  5. Set the corner radius to 6 px and rename the frame Trip / Status Label.

B. Assemble the card

  1. Add heading text Shuttlecraft Trip S-04 with Heading / Medium.
  2. Add secondary text Destination: Starbase 12 with Body / Regular.
  3. Place the status label below the text.
  4. Add two instances of Trip / Detail Row: Departure / 08:30 and Boarding bay / Bay 4.
  5. Select the card's top-level elements and press Shift + A to create a Vertical Auto Layout frame.
  6. Set gap to 12 px, padding to 16 px on all sides, corner radius to 12 px, and height to Hug contents.
  7. Apply Surface / Default as the card fill and add a subtle 1 px border.
  8. Name the assembled frame Trip / Card.
  9. If working on the component by itself, you may preview it at 370 px wide. When using a card instance inside screen-content, set it to Fill container width and Hug contents height.
  10. Set both nested detail rows to Fill container width and Hug contents height.

Sizing note: A 402 px phone with 16 px left/right padding leaves 370 px for the card. That width should result from Fill container, not from hardcoding every card to 370 px. You do not need to set a minimum width or minimum height for this exercise.

6. Create a card component with three variants

22–27 min · One component, different states

  1. Select Trip / Card and choose Create component.
  2. Use Add variant twice so the component set has three variants.
  3. Select the component set and name the variant property Status.
  4. Set the three values to On time, Changed, and Cancelled.
  5. Update each main variant using the matching semantic styles and content:
Status variant Label styles Trip details
On time Surface/Success + Text/Success Departure 08:30; Bay 4
Changed Surface/Warning + Text/Warning Departure 09:15; Bay 6
Cancelled Surface/Danger + Text/Danger State clearly that the mission is cancelled; boarding suspended
  1. Open 03 – Screens. In Assets, find the Trip / Card component and drag an instance into your screen-content frame.
  2. Set that instance to Fill container width and Hug contents height.
  3. Select the card instance. In the right sidebar, use the Status dropdown to switch between On time, Changed, and Cancelled.

Important: Do not communicate the state using color alone. Keep the text label visible. You will select the Cancelled variant on the final prototype screen in Workshop 2.

7. Optional independent challenge: a second language

27–30 min · Instructor previews; students can finish independently

  1. In class, briefly change Departure to Salida programada and observe how the Auto Layout row responds.

  2. Challenge: Back on 02 – Components, select the Trip / Card component set. Add a second variant property named Language with values English and Español.

  3. Create Spanish counterparts for all three statuses. The component set will have six combinations: three Status values × two Language values.

  4. Translate each label, including the status label. For example:

    | English | Spanish | |---|---| | Shuttlecraft trip | Viaje en nave auxiliar | | Destination | Destino | | Departure | Salida programada | | Boarding bay | Bahía de embarque | | On time | A tiempo | | Changed | Modificado | | Cancelled | Cancelado |

  5. Test card instances in both languages inside phone frames. Let longer text wrap; keep the card and rows Fill container in width and Hug contents in height.

  6. Fix anything that clips or overlaps. The status label should continue using Hug contents, so it can stretch with translated text.

Assignment connection: The language variant exercise is optional for this demo, but the Starship Crew App project still requires screens in at least two languages. Your team may choose a different approach to localization.

End-of-class checklist

  • My own Shuttlecraft Trips file in Explorations & Demo, with three pages
  • A 402 × 874 phone frame and four-column guide
  • Two text styles and nine color styles
  • A reusable Trip / Detail Row component
  • A card that uses Auto Layout and adjusts to its container
  • A Trip / Card component with On time / Changed / Cancelled variants
  • Optional: Language variant property with English and Spanish combinations

Connect this to your team project

The shuttlecraft card is a practice example, not a requirement to duplicate the instructor's design. Your team can reuse useful patterns for boarding passes, ID, pay, sickbay, messages, and other sections. Discuss your team's shared component conventions before moving work from your exploration file into the final team project.
